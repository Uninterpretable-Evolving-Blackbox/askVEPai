## How the form gates by species

- Each species checkbox carries classes built at `work/ensembl_source/VEP/InputForm.pm:64-69`: `_stt__var` if `variation` (else `_stt__novar`), `_stt__rfq` if `refseq`, `_stt__pphn` if `variation{POLYPHEN}`, `_stt__sift` if `variation{SIFT}`. Those flags come from `work/ensembl_source/Object_VEP.pm:503-506` (`DATABASE_VARIATION`, `DATABASE_OTHERFEATURES` && `VEP_REFSEQ`, funcgen `Regulatory_Build` count).
- A field with class `_stt_X` is shown when toggle `X` is active; species names become `_stt_Homo_sapiens` etc.
- The whole 'Variants and frequency data' section is classed `_stt_var` (`work/ensembl_source/VEPConstants.pm:47` `'check_has_var' => 1` -> `work/ensembl_source/VEP/InputForm.pm:235`).
- Whether several `_stt_` classes on one field combine as AND or OR is decided in the form's JavaScript, which is not on disk. Where a verdict depends on that, the note says so.
